# 宝塔服务器每日自动更新部署说明

此方案让服务器每天自动运行一次比赛信息采集，并重新生成 `public/` 中的静态网页；Nginx 继续直接提供静态文件。程序源码和数据必须放在网站根目录之外，只有 `public/` 是公网目录。

## 先准备

- 使用宝塔面板「文件」将 `服务器自动更新运行包.zip` 上传到服务器。
- 在宝塔「软件商店」安装 Node.js 24 LTS。此程序没有 npm 第三方依赖，不需要执行 `npm install`。
- 在宝塔「文件」里新建目录：`/www/wwwroot/ai-competition-hub-runtime`。

## 解压运行包

把 ZIP 解压到 `/www/wwwroot/ai-competition-hub-runtime`。解压后应直接看到 `src`、`data`、`public`、`site-config.js`，不要再多套一层同名目录。不要把整个运行包解压进当前网站公开目录。

## 先手动运行一次

在宝塔「终端」中执行：

```sh
cd /www/wwwroot/ai-competition-hub-runtime
node --version
node src/collect.js
```

确认 Node 版本为 24.x，且采集结束后没有致命错误。`data/last-collect.json` 会记录最近一次运行状态；`public/` 是重新生成的网站文件。数据源可能因对方站点临时不可用而显示部分失败，这是采集源的正常风险；程序会尽量保留上次有效数据。若手动运行报错，先不要改网站目录，保存终端报错内容。

## 将网站切换到自动生成目录

切换前，在宝塔「网站」中确认当前站点和 SSL 正常，并备份现有网站根目录。然后打开该站点的「设置」→「网站目录」，只将运行目录改为：

```text
/www/wwwroot/ai-competition-hub-runtime/public
```

保存后访问网站首页及一条详情页，确认页面和 HTTPS 正常。不要把网站目录设为 `/www/wwwroot/ai-competition-hub-runtime`，否则源码和数据可能被公开。

## 添加每日定时任务

在宝塔「计划任务」中添加：

- 任务类型：Shell 脚本
- 执行周期：每天 03:00（服务器时间）
- 脚本内容：

```sh
cd /www/wwwroot/ai-competition-hub-runtime && node src/collect.js >> data/collect-log.txt 2>&1
```

保存后先在计划任务列表点「执行」一次；再检查 `data/collect-log.txt` 和网站首页是否正常更新。若计划任务提示找不到 `node`，回到宝塔终端执行 `which node`，把脚本中的 `node` 替换为返回的完整路径（必须使用服务器实际返回值，不要照抄示例路径）。

## 日常检查与回退

- 每天任务运行后可查看 `data/collect-log.txt`；最近采集状态在 `data/last-collect.json`。
- 采集成功后会自动重建网页；采集失败时会尽量保留上次有效数据。旧数据备份保存在 `data/_backup/`，程序保留最近 5 份。
- 若切换目录后页面异常，可在宝塔「网站目录」把根目录改回原来的路径；不要删除原网站文件或运行包。
- 不要把宝塔账号密码写入脚本、聊天或运行包。
